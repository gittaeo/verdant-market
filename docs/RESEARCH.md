# 뉴스·공시 기반 주식 후보 분석 프로그램 — 사전조사

조사일: 2026-10-25 (한국 시간). 국내 주식, 개인 연구용, 장 마감 후 분석을 초기 가정으로 삼았다. 구현·모델 훈련·실시간 수집·성과 검증은 아직 수행하지 않았다. 아래 서비스 설명은 공개 자료 확인이며 광고 성과를 검증한 것이 아니다.

## 1. 판단

뉴스·공시·재무·가격 자료를 종합해 관심 후보와 판단 근거를 제시하는 프로그램은 만들 수 있다. 실제 초과수익을 내는지는 별도 실험으로 확인해야 한다. 초기 목표는 매일 최대 3~5개 후보에 대해 새로 발생한 재료, 실적 영향, 가격 반영 정도, 위험, 원문 링크를 보여주는 것이다. 근거가 부족하면 후보를 내지 않는다.

처음부터 대규모 모델을 새로 학습할 필요는 없다. 기존 언어모델은 문서에서 사건과 근거를 추출하고 설명하는 역할을 맡고, 수치 계산과 후보 순위는 재현 가능한 규칙으로 시작하는 방안을 제안한다. 데이터와 실제 결과가 쌓인 뒤 별도 예측 모델의 필요성을 판단한다. 이는 설계 제안이며 성능이 입증된 전략은 아니다.

- 사용자가 본 인스타그램 광고의 정확한 서비스는 특정하지 못했다. 위 사례가 해당 광고 제품이라는 뜻은 아니다.

## 4. 관련 연구에서 배운 점

- [Lopez-Lira & Tang, 뉴스 제목을 이용한 주가 반응 연구](https://arxiv.org/abs/2304.07619): 언어모델의 뉴스 해석에 수익률 예측 정보가 존재할 수 있다는 실험 결과를 보고한다. 우리 국내 주식 전략의 수익성을 입증하지는 않는다.
- [Glasserman & Lin, 미래정보 편향 연구](https://arxiv.org/abs/2309.17322): 모델 학습 시기와 과거 시험 시기가 겹치면 이후 결과에 대한 지식이 개입할 수 있고, 기업에 관한 일반 지식도 뉴스 해석에 영향을 줄 수 있음을 다룬다. 과거 뉴스 백테스트만으로 성능을 확정하지 않는다.
- [Chen 외, 과거 수익률에 대한 언어모델 예측 연구](https://arxiv.org/abs/2409.11540): 최근 수익률을 과도하게 연장하고 낙관적으로 전망하는 경향을 보고한다. 최근 급등을 그대로 상승 근거로 쓰지 않도록 실험한다.
- [Bailey 외, 백테스트 과적합](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf): 많은 전략을 시험한 뒤 과거 성과가 가장 좋은 것만 선택하는 문제를 다룬다. 전략 변경과 실험 횟수를 기록하고 평가 구간을 분리한다.

## 5. 제안하는 첫 버전

흐름: 데이터 수집 → 기업/종목 매핑 → 중복 사건 묶기 → 사건·수치·근거 추출 → 가격·재무 확인 → 후보 점수와 위험 평가 → 보고서 → 이후 결과 기록.

1. 코스피·코스닥 보통주 중 충분한 거래대금과 자료가 있는 범위부터 시작한다. 구체적인 유동성 기준은 데이터를 본 뒤 사전에 고정한다.
2. 하루 한 번 장 마감 후 실행한다. 당일 종가를 사용한 분석은 그 종가에 이미 매수한 것으로 계산하지 않는다.
3. 수주, 실적 변화, 자사주, 증자, 전환사채, 규제 등 사건을 분류한다. 보도자료를 옮긴 기사 열 개는 독립 호재 열 개로 계산하지 않는다.
4. 뉴스의 직접 수혜 기업과 단순히 언급된 기업을 구분한다. 전망·소문·확정 공시도 구분한다.
5. 재료의 신규성, 실적 관련성, 출처 신뢰도, 가격/거래량 반응, 위험을 따로 표시한다. 초기 점수는 후보 정렬용이며 상승 확률이 아니다.
6. 최초에는 자의적인 목표가나 확률을 출력하지 않는다. 반대 근거와 관찰 중단 조건을 함께 적는다.

후보 카드 필드:
- 종목명·코드, 분석 기준 시각, 데이터 최신 시각
- 핵심 변화와 사실을 뒷받침하는 원문 링크
- 이익에 영향을 줄 수 있는 경로와 아직 확인되지 않은 가정
- 최근 상승폭·거래량·업종 대비 움직임
- 부정적 공시·희석·재무·유동성 위험과 반대 근거
- 관찰 기간: 예를 들어 5거래일과 20거래일을 별도 평가
- 후보 선정 이유, 제외/재검토 조건, 데이터 누락 여부

기술 초안: Python 수집·계산 + SQLite 저장 + 문서 추출용 언어모델 + 로컬 보고서. 특정 프레임워크 선정이나 웹사이트 제작은 아직 하지 않는다. 비용은 자료 계약, 분석 기업 수, 문서량, 실행 빈도에 좌우되므로 현재 월 비용을 확정하지 않는다.

## 6. 성과 검증 설계

- 게시 시각뿐 아니라 최초 수집 시각·분석 시각을 저장한다. 수정 기사와 정정 재무자료는 버전을 보관한다. 역사적 수집 시각이 없으면 그 한계를 표시한다.
- 당시 거래 가능했던 종목 집합을 사용하고 상장폐지 종목을 누락하지 않는다. 분할·배당·거래정지·체결 불가를 처리한다.
- 시간순으로 학습/조정/최종 평가 구간을 나눈다. 보유기간이 겹치는 표본의 정보 누출도 방지한다.
- 같은 종목 범위에서 단순 가격 전략, 뉴스 없는 전략, 시장/업종 기준과 비교한다. 뉴스가 실제로 추가 가치를 주는지 확인한다.
- 수수료·세금·슬리피지·회전율·유동성 제한을 반영한다. 적용 요율은 구현 시점에 검증한다.
- 상승 적중률만 보지 않고 비용 차감 수익률, 기준 대비 수익률, 최대 낙폭, 거래 횟수, 손익비, 업종 집중도를 본다.
- 결과가 좋았던 후보만 남기지 않고 모든 후보와 미선정 결과를 추적한다. 전략·프롬프트·모델 버전을 기록한다.
- 최초 4~8주 모의 관찰은 운영 오류와 데이터 품질 확인용으로 제안한다. 그 기간만으로 지속적인 초과수익이 입증되는 것은 아니다.

## 7. 이어서 조사/결정할 항목

1. NAVER API HUB의 신규 뉴스 검색 지원과 분석·저장 권한, 다른 뉴스 공급원의 계약 조건.
2. KRX/증권사 데이터의 실제 과거 범위와 수정주가·수급 항목 확보 방법.
3. 특정 사건별 국내 주식 반응과 실적 영향 평가 방법. 재무 숫자 비교 시 계절성·연결 범위·기저효과 반영.
4. 공개 유사 서비스의 성과 공개 방식과 실패 사례 표시 여부. 광고 수익률의 기간·비용·전체 후보 포함 여부.
5. 국내/미국, 단기/중기, 개인용/서비스용 등 범위 확정. 현재는 국내·개인용 가정이다.

이 문서는 후속 대화와 구현의 조사 기록이다. 모델 자체를 영구 재학습한 것이 아니며 자동 조사 일정이나 백그라운드 수집을 설정한 상태도 아니다.
